# zdisamar Data-Oriented Design Index

This index maps current `zdisamar` code to concrete data-oriented design
patterns from Richard Fabian's *Data-Oriented Design*.

Fabian references use the online book links listed in
[`fabian_page_anchors.md`](fabian_page_anchors.md). Printed page numbers are
kept only as orientation hints for the 2018 paper book.

Compiler-output notes for representative lesson shapes live in
[`dod_book/codegen/README.md`](dod_book/codegen/README.md). Those notes compile
small Zig kernels and tie the optimized `arm64` assembly back to the main
lessons.

## Summary

The strongest data-oriented areas are:

- public prepare/run boundaries;
- reusable product and LABOS workspaces;
- dense wavelength sampling and forward-miss plans;
- carrier caches that avoid repeated per-layer spectroscopy work;
- explicit instrumentation facades for feedback;
- boundary separation between input parsing/assets and RTM kernels.

The weakest areas are broad domain aggregates, runtime branch-heavy support for
multiple physics/config modes, and partial use of array-of-structs layouts in hot
model rows. Those are studied separately in `non_data_oriented_divergences.md`.
