# 07. Small Matrix Primitives

The primitive estimate combines real trace counts with the retained `zig build bench` microbench. The point is not that any one primitive is slow: the microbench timings are all sub-microsecond. The point is that the doubling loop calls them millions of times.

For example, one `smul_12x10` call costs about `170.512 ns`, but threshold checks reduce the `R*D`, `T*U`, and `T*D` products to `10,931,496` nonzero products out of `25,168,998` attempted product slots. That nonzero product class estimates to `1.863951 s` of CPU. The q-series package costs about `499.257 ns` when the q-series is known nonzero; `3,408,299` q-series calls estimate to `1.701617 s` of CPU.

The fixed-shape multiply is in [matrix.zig](../../../src/forward_model/radiative_transfer/labos/matrix.zig#L128-L166):

```zig
inline fn smul12x10Into(noalias result: *Mat, a: *const Mat, b: *const Mat) void {
    inline for (0..12) |i| {
        // Load one 12-wide row of a. Only the first 10 Gauss columns
        // participate in the product.
        const a0: @Vector(2, f64) = @splat(a.data[row]);
        const a1: @Vector(2, f64) = @splat(a.data[row + 1]);
        const a9: @Vector(2, f64) = @splat(a.data[row + 9]);

        inline for (0..6) |pair_index| {
            // Two adjacent output columns keep the same 10-term chain per lane.
            const j = pair_index * 2;
            var s = a0 * loadPair(b0, j);
            s += a1 * loadPair(b1, j);
            s += a9 * loadPair(b9, j);
            result.data[row + j] = s[0];
            result.data[row + j + 1] = s[1];
        }
    }
}
```

The fused D update is in [matrix.zig](../../../src/forward_model/radiative_transfer/labos/matrix.zig#L360-L448). The production doubling loop uses the known-right-trace entrypoint so the `T` trace is computed once and reused by the following products:

```zig
fn smulAddSemul3_12KnownRightTrace(threshold_mul: f64, a: *const Mat, e: *const Vec, c: *const Mat, trc: f64) Mat {
    // If Q*T is below threshold, write T + Q*E and skip the multiply.
    if (@abs(tra * trc) <= threshold_mul) {
        result.data[idx] = c.data[idx] + a.data[idx] * ej;
        return result;
    }

    // Otherwise compute Q*T and add T + Q*E in the same output pass.
    result.data[idx] = (c.data[idx] + a.data[idx] * e.data[j]) + s;
}
```

The retained estimates are generated by [labos_bottleneck_summarize.py](../../../validation/performance/labos_bottleneck_summarize.py#L42-L120):


Those estimates sum to `6.041410 s` of primitive CPU. That is larger than the directly timed `4.536551 s` doubling block because the microbench seed is not the exact same data distribution as every in-run matrix and because trace section boundaries are not identical to standalone kernel loops. The value is still useful for ranking: repeated 12x10 matrix products, q-series, and zero-aware elementwise updates are the heavy primitive classes.

The primitive conclusion matches the higher-level trace: there is no single slow call. The final wall is millions of operations that are already small after the [direct fixed-shape matrix work](../why-zdisamar-is-faster/06-direct-12x10-12x12-matrix-calculations.md), [separate output writes](../why-zdisamar-is-faster/12-write-matrix-results-into-separate-outputs.md), and [fused doubling updates](../why-zdisamar-is-faster/05-fuse-layer-doubling-matrix-updates.md).

## Assembly-Level Reading

The assembly-level evidence is generated inside this research folder, not through the forward model or validation build. The command is:

```sh
research/performance/where-is-the-bottleneck/run-primitive-codegen.sh
```

That command builds [primitive-codegen/bench_primitives.zig](primitive-codegen/bench_primitives.zig), runs it with deterministic mock matrices, disassembles the resulting binary, and writes retained artifacts under [primitive-codegen/outputs/](primitive-codegen/outputs/). The summary file is [codegen-summary.md](primitive-codegen/outputs/codegen-summary.md).

The retained `aarch64` run now joins timing and disassembly into this table:

| operation | ns/call | static instructions | ns/static instruction | isolated call-time share | static-instruction share |
| --- | ---: | ---: | ---: | ---: | ---: |
| `smul_12x10` | `169.672` | `2,195` | `0.0773` | `15.86%` | `17.60%` |
| `smul_add_semul3_12` | `187.996` | `2,851` | `0.0659` | `17.57%` | `22.86%` |
| `smul_add_semul3_known_right_trace_12` | `188.876` | `2,842` | `0.0665` | `17.65%` | `22.79%` |
| `qseries_nonzero_12x10` | `519.070` | `4,450` | `0.1166` | `48.51%` | `35.68%` |
| `dot_gauss_pair` | `4.518` | `135` | `0.0335` | `0.42%` | `1.08%` |

These codegen timings are not replacements for the retained `zig build bench` numbers used in the primitive estimate above. They use a different standalone harness so the generated assembly can be retained and read directly.

The instruction count is a static count of the extracted disassembly, not a dynamic retired-instruction count. The `ns/static instruction` column is still useful as an orientation layer: q-series is not merely longer, it also has heavier work per static instruction because the small pivoted solve still has dependent arithmetic and one pivot reciprocal per factorization. The dot pair is only a short arithmetic chain, so it is cheap per call; it becomes visible only because the scattering-order loop calls it `295,581,240` times in the retained spectrum.

This is the useful role for assembly here. It identifies what the expensive primitive classes really are at the machine-code level: repeated floating-point multiply/add chains, plus a heavier small solve in nonzero q-series calls. It does not change the higher-level conclusion that the remaining wall is dominated by repetition counts.

## Simple Python Shape

The primitive estimate is count times cost:

```python
bench_ns = {
    "smul_12x10": 170.512,
    "qseries_nonzero_12x10": 499.257,
}

counts = {
    "smul_12x10": 10_931_496,          # nonzero R*D + T*U + T*D products
    "qseries_nonzero_12x10": 3_408_299,
}

for name, count in counts.items():
    cpu_seconds = count * bench_ns[name] / 1_000_000_000
    print(name, cpu_seconds)
```

A sub-microsecond primitive becomes seconds of aggregate CPU when the count is in the millions.
