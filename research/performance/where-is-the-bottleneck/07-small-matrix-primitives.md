# 07. Small Matrix Primitives

The primitive estimate combines real trace counts with the retained `zig build bench` microbench. The point is not that any one primitive is slow: the microbench timings are all sub-microsecond. The point is that the doubling loop calls them millions of times.

For example, one `smul_12x10` call costs about `155.266 ns`, but the doubling loop performs `25,168,998` of those products across `R*D`, `T*U`, and `T*D`. That product class alone estimates to `3.907890 s` of CPU. The q-series package costs about `519.493 ns` when the q-series is known nonzero; `3,408,299` q-series calls estimate to `1.770587 s` of CPU.

The fixed-shape multiply is in [matrix.zig](../../../src/forward_model/radiative_transfer/labos/matrix.zig#L106-L144):

```zig
inline fn smul12x10Into(noalias result: *Mat, a: *const Mat, b: *const Mat) void {
    inline for (0..12) |i| {
        // Load one 12-wide row of a. Only the first 10 Gauss columns
        // participate in the product.
        const a0 = a.data[row];
        const a1 = a.data[row + 1];
        const a9 = a.data[row + 9];

        inline for (0..12) |j| {
            // One output cell is a 10-term multiply-add chain.
            var s = a0 * b0[j];
            s += a1 * b1[j];
            s += a9 * b9[j];
            result.data[row + j] = s;
        }
    }
}
```

The fused D update is in [matrix.zig](../../../src/forward_model/radiative_transfer/labos/matrix.zig#L279-L352):

```zig
fn smulAddSemul3_12(threshold_mul: f64, a: *const Mat, e: *const Vec, c: *const Mat) Mat {
    // If Q*T is below threshold, write T + Q*E and skip the multiply.
    if (@abs(tra * trc) <= threshold_mul) {
        result.data[idx] = c.data[idx] + a.data[idx] * ej;
        return result;
    }

    // Otherwise compute Q*T and add T + Q*E in the same output pass.
    result.data[idx] = (c.data[idx] + a.data[idx] * e.data[j]) + s;
}
```

The retained estimates are generated by [labos_bottleneck_summarize.py](../../../validation/performance/labos_bottleneck_summarize.py#L39-L98):

```python
operations = [
    (
        "qseries package",
        "matrix_qseries",
        "qseries_nonzero_12x10",
        "qseriesKnownNonzeroProduct",
    ),
    (
        "R*D, T*U, T*D products",
        "matrix_smul_rd+matrix_smul_tu+matrix_smul_td",
        "smul_12x10",
        "three 12x10 products inside every doubling step",
    ),
    (
        "D update",
        "matrix_smul_add_semul3",
        "smulAddSemul3_12",
        "T + Q*diag(E) + Q*T fused update",
    ),
]

count = sum(counters[name] for name in counter_expr.split("+"))
ns_per_call = bench[bench_name]
estimated_ns = count * ns_per_call
```

Those estimates sum to `8.359756 s` of primitive CPU. That is larger than the directly timed `6.036863 s` doubling block because the microbench seed is not the exact same data distribution as every in-run matrix and because trace section boundaries are not identical to standalone kernel loops. The value is still useful for ranking: repeated 12x10 matrix products and q-series are the heavy primitive classes.

The primitive conclusion matches the higher-level trace: there is no single slow call. The final wall is millions of operations that are already small after the [direct fixed-shape matrix work](../why-zdisamar-is-faster/06-direct-12x10-12x12-matrix-calculations.md), [separate output writes](../why-zdisamar-is-faster/12-write-matrix-results-into-separate-outputs.md), and [fused doubling updates](../why-zdisamar-is-faster/05-fuse-layer-doubling-matrix-updates.md).
